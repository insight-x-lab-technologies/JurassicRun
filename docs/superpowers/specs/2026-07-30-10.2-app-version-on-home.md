# Spec 10.2 — Versão do jogo visível na Home

**Item:** Fase 10, Frente A, 10.2 (`docs/roadmap/PHASE-10-polish-and-portrait.md`).
**Pedido original do usuário (#9):** não dá para saber que versão do jogo está rodando no aparelho.

## Problema

O jogo não expõe versão nenhuma na UI. Ao validar num celular (o fluxo normal desta fase), não há
como distinguir um build novo de um build velho servido pelo Service Worker — que é exatamente o
gotcha recorrente do projeto ("SW cacheia `dist` antigo"). Uma versão visível transforma esse
diagnóstico numa olhada na tela.

## Resultado desejado

Rodapé da Home mostra a versão do `package.json` (hoje `1.0.0`) como `v1.0.0`, em texto pequeno e
muted, sem custo de layout e sem string traduzível nova.

## Decisões técnicas (tomadas sem gate humano)

### D1 — Injeção em build time via `define`, com um helper compartilhado

A versão vem do `package.json` — fonte única da verdade — injetada como a constante global
`__APP_VERSION__`. **Nada de `import pkg from '../../package.json'` no código do app**: isso puxaria
o JSON inteiro (deps, scripts) para dentro do bundle. `define` faz substituição textual: o bundle
final carrega só a string `"1.0.0"`.

Helper novo `src/build/appVersion.ts` lê e valida o `package.json`, usado pelos **dois** configs.

### D2 — `define` precisa entrar em `vite.config.ts` **E** `vitest.config.ts` (gotcha)

Os dois configs deste projeto são **arquivos separados e independentes** (`vitest.config.ts` não
estende o `vite.config.ts`). Declarar `define` só no config do Vite faz **todo teste que renderiza a
Home** morrer com `ReferenceError: __APP_VERSION__ is not defined`, porque o Vitest nunca substitui o
identificador. Os dois configs recebem o `define`, ambos alimentados pelo helper de D1 — assim o
teste compara o texto renderizado com o valor **real** do `package.json`, e não com um literal
duplicado que pode dessincronizar.

### D3 — Tipagem via `src/types/globals.d.ts`

O projeto hoje não tem **nenhum** `.d.ts`. Criar um com `declare const __APP_VERSION__: string;`.
Cai dentro do `include: ["src", ...]` do `tsconfig.json`, então não exige mexer em config de TS.

### D4 — Posição: mesma linha do copyright, não elemento novo empilhado

O requisito do roadmap é "fora do fluxo do menu (não pode empurrar o CTA em paisagem baixa —
precedente 9.9)". A leitura literal seria `position: absolute`, **mas `.home` é
`overflow-y: auto`** (`global.css:290`): dentro de um container que rola, um filho absoluto ancora no
conteúdo, não na viewport — ou seja, ele rolaria junto e poderia sobrepor o menu. Solução escolhida:
a versão vira um `<span>` **inline, na mesma linha do `<p class="home__copyright">` já existente**.

Custo de altura: **zero** — nenhuma linha nova é criada, o CTA não se move em nenhuma orientação.
Atende o objetivo real do requisito (não empurrar o CTA) sem o risco do absolute em scroll container.

### D5 — Sem chave i18n

Formato `v1.0.0`, só dígitos e o prefixo `v` — nenhuma palavra traduzível, conforme o roadmap. REGRA
4 não é violada porque não há texto de idioma. Se um dia levar rótulo ("Versão: …"), aí vira chave.

### D6 — Bump manual ao fechar cada fase

Documentar em `docs/WORKFLOW.md`: ao fechar uma fase, subir `version` do `package.json`. Sem
automação (semantic-release e afins são peso desnecessário para hobby project).

## Escopo

**Dentro:** helper de versão, `define` nos dois configs, tipo global, render do span na Home, CSS,
testes, doc do bump em `WORKFLOW.md`, item marcado no arquivo da fase.

**Fora:** tela "Sobre", exibição de git SHA/data de build, versão em outras telas, automação de bump,
mostrar versão no Game Over/Settings.

## Aceite

1. Home renderiza `data-testid="app-version"` com o texto `v` + `version` do `package.json`.
2. O teste **lê o `package.json`** para montar o esperado (não usa literal `'1.0.0'` hardcoded) ⇒ o
   bump de versão não quebra o teste nem passa despercebido.
3. `npm test` inteiro verde — em especial os testes de Home/App que antes explodiriam por D2.
4. `npm run check` limpo (inclui o `.d.ts` novo).
5. Nenhuma chave i18n nova; guardas de paridade e scanner AST continuam verdes.
6. `src/core/` intocado ⇒ determinismo permanece em 73 testes, sem re-pin de golden.
7. A versão não adiciona altura ao rodapé: o CTA "Jogar" continua na mesma posição em paisagem baixa.
