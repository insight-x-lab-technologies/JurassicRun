# 10.8 — Loja com compra real de moedas (design)

**Item:** Fase 10, Frente C, item 10.8 (`docs/roadmap/PHASE-10-polish-and-portrait.md:310`).
**Data:** 2026-07-31. **Toca `src/core/`:** não ⇒ determinismo permanece **73**.

## Problema

`ShopScreen.tsx:33` chama `walletService.earn(pack.coins)` no clique do pacote: **1 clique = moedas
de graça**. O texto `shop.honorNote` até admite ("as moedas são adicionadas na hora, sem pagamento"),
mas isso torna a economia inteira decorativa — carteira, preço de expansão e qualquer troféu ligado a
moeda viram ruído. Pior: a tela é um `if` de duas caras — **ou** o formulário de resgate (quando há
gateway) **ou** os pacotes grátis (quando não há). O jogador nunca vê as duas coisas, e sem gateway
não existe nenhum caminho honesto de compra.

Secundário, descoberto na leitura: **não existe nenhum CSS de `.shop*`/`.redeem*`** em
`global.css` — a Loja renderiza com estilo genérico de `.screen`.

## Decisões travadas (fase) que este item obedece

- **Sem checkout próprio.** Nenhum processador de pagamento (Stripe & cia): custo, KYC e fora do
  escopo hobby. O pagamento acontece **no Ko-fi**; o jogo só resgata o código emitido depois
  (fluxo 8.4 já existente: Edge Function + claim atômico single-use).
- **As 3 seções sempre visíveis**: saldo · pacotes com preço em dinheiro real · resgate de código.
  Sem gateway, o resgate aparece **desabilitado com aviso**, não escondido.
- **Preços/URLs por SKU vêm de configuração**, não de literal no JSX.

## Arquitetura

Molde do projeto: **puro × casca**. Dado e regra em módulo puro testável; IO (abrir aba, ler
`import.meta.env`) só na borda.

### 1. `src/services/purchase/storefront.ts` (novo, puro)

Fonte única de preço e destino de compra. Espelha `src/services/online/config.ts` (parser puro sobre
um objeto env-like + casca que lê `import.meta.env`).

```ts
export type CoinSkuId = 'small' | 'medium' | 'large';
export interface PriceTag { readonly amountMinor: number; readonly currency: string }
export interface Storefront {
  readonly kofiUrl: string;
  readonly prices: Readonly<Record<CoinSkuId, PriceTag>>;
}

export const KOFI_PAGE_URL = 'https://ko-fi.com/insightxlabgamestudio';
export const DEFAULT_STOREFRONT: Storefront;      // 199 / 499 / 999 USD (minor units)

export function parseStorefront(env: Record<string, unknown>): Storefront;  // nunca lança
export function formatPrice(price: PriceTag, locale: string): string;
export function checkoutUrlFor(sf: Storefront, sku: Sku): string;
export function storefront(): Storefront;          // casca: import.meta.env
```

Pontos travados:

- **Valores em unidades menores** (`amountMinor: 199`), inteiros. Nada de float de dinheiro.
- **Defaults funcionam sem `.env`** (offline-first, REGRA do projeto): sem configuração a loja
  mostra preço e CTA corretos. `parseStorefront` só **sobrescreve** o que vier válido, campo a
  campo — env quebrado nunca derruba a tela. Chaves: `VITE_SHOP_KOFI_URL`,
  `VITE_SHOP_CURRENCY`, `VITE_SHOP_PRICE_SMALL|MEDIUM|LARGE` (inteiro em unidades menores).
- **Preço formatado por `Intl.NumberFormat`** com a língua ativa do i18n (`style: 'currency'`), com
  fallback `"USD 1.99"` se o `Intl` recusar a moeda. Zero chave i18n para o preço em si.
- **`checkoutUrlFor`** anexa `jr_sku=<sku>` à URL do Ko-fi (`?` ou `&` conforme a base), de forma
  que o pedido chegue rastreável. Como o Ko-fi não garante prefill de mensagem, a UI **também
  mostra o código do SKU** com instrução de colar na mensagem — é isso que fecha o ciclo manual de
  fulfillment descrito em `supabase/README.md:37`.
- **Guarda de sincronia:** teste prova `KOFI_PAGE_URL === DONATE_OPTIONS(kofi).url`. Duas telas
  apontando para páginas diferentes do mesmo estúdio seria um bug silencioso. (Molde do teste de
  paridade catálogo × gerador do 10.6.)

### 2. `src/app/openUrl.ts` (novo) e refactor mínimo de `donate.ts`

`donate.ts` já tem o abridor injetável (`openUrl` em deps, `window.open(url,'_blank','noopener')` na
casca). A Loja precisa do mesmo. Extraio `openExternal(url, deps)` + `defaultOpenDeps()` para um
módulo próprio e `donate.ts` passa a delegar — **assinatura pública de `openDonation` intocada**, os
testes de doação continuam válidos. Sem isso, seriam duas cópias do mesmo `try/catch`.

### 3. `src/app/shop/packs.ts`

`CoinPack` ganha `sku: Sku` (`'coins:small'`…). Hoje a tela conhece a quantidade mas não o SKU, e o
SKU é justamente o que precisa viajar na URL e na mensagem do Ko-fi.

### 4. `ShopScreen.tsx` — reescrita

Ordem das seções (todas sempre montadas):

1. **Saldo** (`shop-balance`, inalterado).
2. **Pacotes**: por pacote — quantidade de moedas, **preço formatado**, botão
   `shop-buy-<id>` que abre `checkoutUrlFor(...)` em nova aba, e o código do SKU visível.
   Nota fixa: o pagamento acontece no Ko-fi e devolve um código.
3. **Resgate**: `<RedeemCodeForm />` **sempre montado**. Sem gateway (`purchaseService.available`
   falso), input e botão ficam `disabled` e um aviso explica.
4. **Moedas de graça**: como conseguir moeda sem pagar.
5. Expansões em breve + voltar (inalterados).

**Nenhum handler da Loja toca `walletService`.** O único caminho para moeda paga é
`purchaseService.redeem(code)` → gateway → `wallet.earn` **dentro do serviço**.

### 5. `RedeemCodeForm.tsx`

Passa a ler `purchaseService.available.value` e desabilitar-se, mostrando `shop.gatewayOffline`.
Antes essa decisão vivia no `ShopScreen` (o `if` que escondia tudo); ela pertence ao formulário.

### 6. CSS

Blocos `.shop__*`, `.shop-pack`, `.redeem*` em `global.css`. Teto de largura vai nos **filhos** com
`margin-inline: auto` — nunca na raiz `.screen shop` (invariante do 10.5, com guarda automática em
`tests/app/screen-root-width.test.ts`).

## Fontes gratuitas: desvio consciente do texto do roadmap

O roadmap pede explicitar "jogar, desafios, **troféus**". Verificado: `walletService.earn` só tem
**dois** call sites de gameplay — `startGame.ts:99` (`coinsForFood(w.food)`, que roda para
`endless`, `daily` e `weekly`) e o próprio `purchase`. **Troféus não creditam moeda nenhuma.**
Listar troféu como fonte de moeda seria texto falso na UI. A seção lista as duas fontes verdadeiras
(partidas e desafios). Fazer troféu pagar moeda é mudança de economia — item de outra fase (11
"economia viva"), não deste.
