# 10.4 — "Moedas" no lugar de "comida" na UI · Plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** a UI inteira passa a falar "moedas"; nomes internos (`food`) ficam intocados.

**Architecture:** duas naturezas de mudança, uma task cada. Task 1 renomeia as **chaves** i18n
(`hud.food`→`hud.coins`, `gameover.food`→`gameover.coins`, `leaderboard.food`→`leaderboard.coins`)
nos 10 locales e nos 4 pontos de uso, e colapsa as duas linhas duplicadas do Game Over numa só.
Task 2 troca o **texto** de chaves cujo id é código e não muda (`trait.doubleFood`,
`trait.tripleFood`, `powerup.doubleCoin`, `trophy.forager.desc`).

**Tech Stack:** TypeScript estrito, Preact, i18next (10 locales JSON), Vitest + happy-dom.

**Spec:** `docs/superpowers/specs/2026-07-30-10.4-coins-not-food-ui.md`

## Global Constraints

- **`src/core/` INTOCADO.** Determinismo permanece em 73 testes.
- **Nada de renomear campo interno:** `WorldState.food`, `TrophyStats.totalFood`, `coinsForFood`,
  `GameOverRaw.food`/`GameOverView.food`, `HudRaw.food`/`HudView.food`, `LeaderboardEntry.food`, a
  coluna `food` do Supabase e os ids `doubleFood`/`tripleFood`/`doubleCoin` FICAM COMO ESTÃO.
  Renome de campo = re-pin de hash/goldens sem ganho para o jogador.
- **REGRA 4 (i18n):** nenhuma string visível hardcoded; **os 10 locales** (`en`, `pt-BR`, `es`,
  `fr`, `de`, `it`, `ja`, `ko`, `zh`, `hi`) mudam juntos. Guardas `tests/i18n/locales.test.ts`
  (paridade + placeholders) e `tests/i18n/no-hardcoded-strings.test.ts` (scanner AST) têm de
  continuar verdes. Use a skill `add-locale` como referência do formato.
- **Preservar a pontuação de cada locale** ao renomear a chave: `fr` usa `Pièces : {{value}}` (espaço
  antes dos dois-pontos) no Game Over e `Pièces: {{value}}` no HUD; `zh` usa `：` (largura cheia) no
  Game Over e `:` no HUD. Copie os valores das tabelas abaixo VERBATIM.
- **Placeholder `{{value}}`** tem de sobreviver em toda chave que já o tinha (a guarda de paridade
  compara os placeholders entre locales).

```ts
import { describe, it, expect } from 'vitest';
import { SUPPORTED_LANGUAGES, resources } from '@i18n/locales/index';

function keyPaths(obj: Record<string, unknown>, prefix = ''): string[] {
  return Object.entries(obj).flatMap(([k, v]) => {
    const path = prefix ? `${prefix}.${k}` : k;
    return v !== null && typeof v === 'object'
      ? keyPaths(v as Record<string, unknown>, path)
      : [path];
  });
}

// 10.4: a UI fala "moedas". Guarda sobre as CHAVES (verificável nos 10 idiomas), não sobre os
// textos traduzidos — caçar a palavra "comida" em 10 línguas exigiria um dicionário que o projeto
// não tem como manter. Ids de código como `trait.doubleFood` seguem permitidos: são ids, não a
// palavra na tela.
describe('vocabulário de moeda', () => {
  it('nenhum locale tem uma chave chamada `food`', () => {
    for (const lang of SUPPORTED_LANGUAGES) {
      // `resources[lang]` é `{ translation: {...} }` — o dicionário fica sob `.translation`.
      const offenders = keyPaths(resources[lang].translation).filter((p) =>
        p.split('.').includes('food'),
      );
      expect(offenders, `locale ${lang}`).toEqual([]);
    }
  });
});
```
