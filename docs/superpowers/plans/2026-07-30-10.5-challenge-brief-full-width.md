### Task 1: guarda de invariante + raiz full-bleed

**Files:**
- criar `tests/app/screen-root-width.test.ts`
- editar `src/app/styles/global.css`

**Step 1 — teste (vermelho primeiro):** `tests/app/screen-root-width.test.ts`, ambiente node
(sem `@vitest-environment`; o teste só lê arquivos com `node:fs`/`node:path` — ver gotcha do 10.2:
com DOM, `fileURLToPath(new URL(...))` quebra).

Invariante:

> Toda classe usada como raiz de tela — extraída de `src/app/screens/*.tsx` pelo padrão
> `class="screen <modificadora>"` — que declare `max-width` em `src/app/styles/global.css` precisa
> declarar, **no mesmo bloco**, `margin-inline: auto` ou `align-self: center`.

Razão: `#app` é `display:flex; flex-direction:column` com `align-items` default `stretch`; um item
com largura resolvida não estica e assenta à esquerda. O teto em si não é o erro — teto **sem
centralização** é.

Implementação sugerida:
1. `readdirSync('src/app/screens')` filtrando `.tsx`; para cada arquivo, regex
   `/class="screen\s+([^"]+)"/g` ⇒ conjunto de classes modificadoras (ex.: `challenge-brief`).
2. Ler `global.css` e casar blocos com `/([^{}]+)\{([^{}]*)\}/g` — declarações sem `{` ⇒ os
   cabeçalhos `@media` caem fora sozinhos e as regras **dentro** deles são cobertas.
3. Para cada bloco cujo seletor contenha o token exato `.<classe-raiz>`: se as declarações têm
   `max-width`, exigir `margin-inline: auto` ou `align-self: center` no mesmo bloco. Mensagem de
   falha citando o seletor.
4. Um segundo teste barato de sanidade do extrator: o conjunto de classes-raiz não pode ser vazio
   e tem de conter `challenge-brief` (senão um refactor de JSX desliga a guarda em silêncio).

Rodar e **ver falhar** citando `.challenge-brief` antes de tocar no CSS.

**Step 2 — fix:** em `src/app/styles/global.css`:
- `.challenge-brief` (bloco base, ~linha 920): remover `max-width: 32rem`, mantendo `width: 100%` e
  o `gap`. Atualizar o comentário do bloco explicando o padrão (teto nos filhos, nunca na raiz, com
  o porquê do `stretch` do `#app`).
- adicionar teto centrado aos três blocos de conteúdo:
  ```css
  .challenge-brief__stats,
  .challenge-brief__rules,
  .challenge-brief__actions {
    max-width: 44rem;
    margin-inline: auto;
  }
  ```
  (44rem = mesmo teto do `.leaderboard__list`.) Manter as declarações que esses blocos já têm; o
  `width: 100%` deles permanece.
- não mexer nas regras de `@media` existentes.

**Step 3 — verificar:** `npx vitest run tests/app/screen-root-width.test.ts tests/app/challengeScreen.test.tsx`
verde, depois **`npm test` inteiro** e `npm run check` (precedente 9.8: rodar só os arquivos-alvo
esconde quebras).

**Verify:** guarda vermelha antes / verde depois; suíte inteira verde; `check` limpo; `git diff`
mostra apenas o CSS e o teste novo.

### Task 2 (controlador, inline): medição por NÚMERO no navegador

Não é para subagente — usa Playwright via MCP.

- `npm run build` e servir o `dist`; abrir com `?nocache`, `serviceWorker.getRegistrations()` +
  `unregister()` e `caches.keys()` + `delete()` antes de medir (gotcha recorrente).
- Navegar até o briefing Diário e o Semanal (Home → Desafio) em **740×360**, **640×360** e um
  retrato (**390×844**).
- Medir com `getBoundingClientRect()`/`getComputedStyle`:
  - largura útil = `clientWidth` da `.screen` menos `padding-left/right`;
  - `.challenge-brief__stats` ocupa ≥99% da largura útil;
  - simetria das folgas laterais (`box.left - useful.left ≈ useful.right - box.right`, tolerância 1px);
  - `bottom` do `[data-testid="challenge-play"]` ≤ `innerHeight` em 740×360 (CTA sem rolagem).
- Registrar os números medidos no relatório de fechamento.
